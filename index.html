제안 포인트

① 개발 언어·방식 제안과 선택 이유

"사용자 웹 + Android/iOS 앱 + 관리자 웹"을 예산·기간 안에 만드는 가장 효율적인 방법은 사용자용 3종(웹·Android·iOS)을 코드 하나로 만들고, 관리자 웹만 따로 만드는 것입니다.

구분제안 기술선택 이유 (비개발자 관점)
사용자 웹 + Android + iOSFlutter (구글이 만든 크로스플랫폼 도구)한 번 만든 화면이 웹·Android·iOS에 똑같이 나옵니다. 따로 3개를 만들 때보다 개발 기간과 비용이 크게 줄고, 출시 후 수정도 한 곳만 고치면 3곳에 반영됩니다.
관리자 웹Next.js (React 기반 웹)표·검색·필터·통계 차트가 많은 업무 화면에 가장 적합하고, 검증된 관리자 화면 부품을 활용해 빠르게 만듭니다. PC 브라우저에서 바로 사용합니다.
서버 + DBNestJS + PostgreSQL웹·앱·관리자 웹이 같은 서버를 함께 씁니다. 예약 상태·회원 승인 같은 규칙을 서버 한 곳에서 관리해 화면마다 결과가 달라지는 일이 없습니다.
푸시 알림Firebase FCM가입 승인·예약 확정 알림을 Android·iOS에 무료로 보냅니다. 웹 사용자는 사이트 내 알림함으로 같은 내용을 확인합니다.
클라우드AWS (발주처 명의 계정)초기 규모에 맞는 작은 서버로 시작해 월 운영비를 낮추고, 회원이 늘면 사양만 올리면 됩니다. 숙소 이미지는 S3에 저장합니다.

왜 사용자 웹도 Flutter인가요? 일반적으로 Flutter 웹은 검색엔진 노출(SEO)이 약한 편이지만, 본 서비스는 승인된 회원만 로그인해서 쓰는 회원제 서비스라 검색 노출이 필요 없습니다. 그래서 웹을 따로 만들 이유가 없고, 앱과 같은 코드로 만드는 것이 가장 경제적입니다.

예상 월 운영비(발주처 부담)는 초기 회원 수천 명 기준 AWS 월 5~10만원 수준이며, 푸시(FCM)는 무료입니다.

② 아이디어 단계에서 기능을 구체화하는 협업 방식

  • 킥오프 + 기능 확정 미팅 2회 (1~2주차): 준비하신 기능 구성안을 바탕으로 화면 흐름을 함께 그리며 "1차 출시 필수 / 추후 고도화"를 나눕니다. 미팅 다음 날까지 결정 사항을 정리한 회의록을 공유합니다.
  • 눌러볼 수 있는 화면 시안: 디자인 단계에서 Figma 클릭형 시안 링크를 드려 실제 앱처럼 눌러 보며 의견을 주실 수 있게 합니다. 개발 전에 화면을 확정해 뒤늦은 변경을 줄입니다.
  • 매주 직접 써 보기: 5주차부터 매주 테스트 앱(TestFlight·구글 내부 테스트)과 테스트 웹 주소를 드려 진행 상황을 직접 확인하실 수 있습니다.
  • 상사 보고에 그대로 쓰는 주간 보고: 매주 금요일 진척률·완료 기능·이슈·다음 주 계획을 한 장으로 정리해 드립니다. 내부 보고 자료로 바로 쓰실 수 있습니다.
  • 상시 소통: 카카오톡 단톡방(평일 업무시간 내 당일 회신), 주 1회 30분 화상 데모, Notion 일정 보드 상시 공유

③ 기간·비용이 늘어나지 않도록 하는 범위 관리

  • 범위 확정 시점: Day 14 기획·화면 설계 승인으로 1차 출시 범위를 확정하고, 이후 추가 요청은 영향(기간·비용)을 먼저 알려 드린 뒤 결정하시도록 합니다.
  • "추후 고도화" 목록 관리: 좋은 아이디어지만 1차에 꼭 필요하지 않은 기능은 목록으로 따로 모아 출시 후 2차 개발 자료로 넘겨 드립니다.
  • 고정 금액: 확정 범위 안에서는 추가 비용이 없습니다.

④ 스토어 심사 대비 (회원제 앱 특성 반영)

  • 승인 전 회원이 아무것도 못 보면 심사에서 반려될 수 있어, 심사용 데모 계정과 "회원제 서비스" 안내 문구·승인 대기 화면을 처음부터 설계합니다.
  • 앱 안에서 회원탈퇴 (양 스토어 필수), 개인정보처리방침, 사진 접근 권한 안내 문구, 구글 Data Safety·애플 개인정보 라벨 작성
  • 이메일(또는 휴대폰) 가입 방식이면 Apple 로그인 의무가 없어 일정이 단순해집니다. 소셜 로그인 추가 여부는 미팅에서 결정합니다.
  • Day 45에 테스트 빌드를 먼저 제출해 반려 요인을 미리 확인하고, Day 60 정식 심사 제출로 대응 여유를 둡니다.

PRD (Product Requirements Document)

공고 내용을 바탕으로 정리한 초안이며, 1~2주차 기능 확정 미팅에서 함께 최종 확정합니다.

1. 프로젝트 배경 및 목적

당사와 제휴된 숙박업체를 승인된 회원만 온라인으로 간편하게 예약할 수 있는 전용 웹·앱이 필요합니다. 숙박업체 직원이 별도 시스템을 쓰지 않아도, 회원의 예약 신청을 당사 관리자가 관리자 웹에서 즉시 확인하고 처리하는 구조입니다.

  • 목표 1: 승인된 회원만 이용하는 회원제 예약 서비스 (웹·Android·iOS)
  • 목표 2: 예약 신청 → 관리자 확인·확정 → 회원 푸시 알림까지 한 흐름으로 연결
  • 목표 3: 배너 광고와 기본 통계로 운영 현황 파악
  • 제약: 결제 제외, 꼭 필요한 핵심 기능 위주, 2.5개월 내 스토어 출시

2. 사용자 정의

승인 회원관리자 승인 완료 회원숙소 조회, 예약 신청·확인·취소, 리뷰 작성·신고, 마이페이지, 알림
당사 관리자서비스 운영 담당가입 승인, 사업체·객실 관리, 예약 처리, 배너 광고, 리뷰 신고 처리, 통계

4. 기능 요구사항

4.1 사용자 웹 및 모바일 앱 (Android / iOS)

  • [필수] 회원가입 신청(이름·연락처·소속 등 항목은 미팅에서 확정), 승인 완료 회원만 로그인·이용 권한 제어, 승인 대기·반려 안내, 회원탈퇴
  • [필수] 메인 배너 광고 노출, 제휴 숙소 목록(지역·검색 필터), 숙소 상세(소개·객실 안내·이미지·위치 지도·편의시설)
  • [필수] 예약 신청: 체크인·체크아웃 일자, 객실, 인원 선택 (결제 없음), 예약 불가 날짜 표시
  • [필수] 예약 내역·상태(예약대기·예약확정·이용완료·예약취소) 확인, 취소 요청
  • [필수] 이용완료 회원의 별점·텍스트·사진 리뷰 작성, 숙소별 리뷰 목록, 부적절 리뷰 신고
  • [필수] 마이페이지(회원정보 수정), 알림함(가입 승인·예약 푸시 내역), 공지사항

4.2 관리자 웹 (백오피스)

  • [필수] 신규 가입 신청 확인·승인/반려(사유), 전체 회원 목록·상태(정상·정지·탈퇴) 관리
  • [필수] 제휴 사업체 기본 정보·이미지, 하위 객실 정보, 이용 안내, 예약 가능 여부(날짜별 마감) 등록·수정
  • [필수] 예약 내역 목록·달력 보기, 예약 확정·변경·취소 처리, 신규 예약 표시
  • [필수] 배너 광고 등록·노출 기간·순서 관리, 공지사항 등록, 리뷰 신고 처리(숨김·삭제)
  • [필수] 통계 대시보드: 기간별 회원 가입 수, 예약 현황(상태별·숙소별), 광고 노출·클릭 수

4.3 시스템 공통 및 스토어 배포

  • [필수] 사용자 웹·Android·iOS를 Flutter 단일 코드로 통합 구축
  • [필수] 가입 승인·예약 상태 변경 FCM 푸시
  • [필수] 클라우드 서버·DB 구축, 구글 플레이스토어·애플 앱스토어 정식 출시

  • 애플·구글 개발자 계정은 발주처 명의 — 법인 애플 계정 신규 생성 시 D-U-N-S 번호 발급에 1~2주가 걸려 계약 직후 신청 필요
  • 제휴 숙소 리스트·기본 정보·이미지는 발주처 준비 → 초기 일괄 등록 양식(엑셀) 제공
  • 운영 중 AWS 이용료, 스토어 등록비, 도메인 비용은 발주처 부담
